# Security Policy

## Supported versions

Only the latest release receives security fixes.

| Version | Supported |
|---------|-----------|
| latest release | :white_check_mark: |
| older releases | :x: |

## Reporting a vulnerability

**Please do not open a public issue for security reports.**

Report vulnerabilities privately through **GitHub Security Advisories** on this repository
(*Security* tab → *Report a vulnerability*). Include a description, reproduction steps, and
the affected version/commit if known.

We will acknowledge your report, investigate, and coordinate a fix and disclosure timeline
with you.

## Scope notes

This repository contains only the agent (client side). Some relevant security properties:

- **Agent token compromise** — the agent token in `/etc/mojatools-agent/token` authenticates
  pushes for one host. If you suspect it leaked, **revoke the agent from the mojatools admin
  panel**; the token immediately stops being accepted. Then re-enroll with a fresh
  enrollment token.
- **Enrollment tokens** — generated by the mojatools server, **one-time use** and valid for
  **24 hours** only. A leaked unused enrollment token can mint a new agent; revoke it in the
  panel if it hasn't been consumed.
- **Server-pushed config** — the agent treats all server responses as *data*, validates them
  against a strict whitelist, and never executes anything derived from them. TLS certificate
  verification is always on and cannot be disabled.
- **Docker group** — installing with `--enable-docker` grants the agent user membership in
  the `docker` group, which is effectively root-equivalent on the host. This is an explicit,
  warned-about opt-in.

Vulnerabilities in the mojatools **server** itself are out of scope for this repository's
advisory process unless they manifest through the agent's public API contract.
